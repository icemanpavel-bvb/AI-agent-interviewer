## Как читать план

План разбит на **этапы 0–7**. Каждый этап заканчивается работающим результатом, который можно показать куратору.
Внутри этапа указаны задачи, рекомендуемый исполнитель (по §13) и **критерий готовности**: пока он не выполнен, этап не закрыт.
Оценка сроков дана для команды из 4 человек при занятости примерно 6–8 часов в неделю на каждого.

| Этап | Результат | Срок |
|---|---|---|
| 0. Подготовка | Ответы заказчика, репозиторий, выбрана модель | 1 неделя |
| 1. Фундамент | БД, миграции, авторизация, CRUD вакансий | 1–1,5 недели |
| 2. Диалог без AI | Кандидат проходит интервью по ссылке, вопросы идут строго по сценарию | 1,5 недели |
| 3. AI-шаги | Анализ полноты, уточнения, ответы на вопросы кандидата, guardrails | 2 недели |
| 4. Протокол | JSON с цитатами + проверки + PDF + уведомление | 1,5 недели |
| 5. Кабинет рекрутера | Просмотр и правка отчёта, решения, «Отложенные» | 1,5 недели |
| 6. Качество | Синтетические диалоги, метрики, доработка промптов | 1 неделя |
| 7. Пилот и сдача | Замер KPI, документация, демо | 1 неделя |

Этапы 2 и 5 частично идут параллельно: фронтенд кабинета можно делать на моковых данных, пока бэкенд занят AI-частью.

## Этап 2. Диалог без AI (каркас интервью)

Цель — собрать полный путь кандидата, **ещё не подключая LLM**. Вместо анализа ответа считаем, что ответ всегда полный. Так автомат диалога и сохранение отлаживаются отдельно от модели.

### 2.1. Interview Engine, детерминированная часть (Кондратов)
- [ ] `engine.start / accept_consent / handle_turn` по схеме `02_interview_fsm.svg`.
- [ ] Блокировка сессии `SELECT … FOR UPDATE`, защита от повторной отправки (идемпотентность по `client_message_id`).
- [ ] Возобновление: при повторном открытии ссылки отдаётся вся история и текущий вопрос.
- [ ] Истёкшая или завершённая ссылка возвращает понятную ошибку (410), а не 500.
- [ ] Тексты без LLM в `interview/messages.py`: приветствие, согласие, переходы, прощание.

### 2.2. API кандидата (Кондратов)
- [ ] `GET /interview/{token}`, `POST /consent`, `POST /messages`.
- [ ] Ограничения: длина сообщения ≤ 2000 символов, rate-limit (например, 10 сообщений в минуту на токен).

### 2.3. Чат кандидата (Щербакова)
- [ ] Экран согласия → чат → экран завершения.
- [ ] Прогресс «Вопрос 3 из 8», индикатор «ассистент печатает», мобильная вёрстка.
- [ ] При перезагрузке страницы история восстанавливается с сервера.
- [ ] Демо-страница `/demo` (D-005): карточки сценариев, кнопка «Начать», бэкенд `api/v1/demo.py` при `DEMO_MODE=true`.

### 2.4. Тесты (Мальцева)
- [ ] Интеграционный тест: прохождение интервью из 3 вопросов от начала до конца.
- [ ] Тест: кандидат ушёл после 2-го вопроса, вернулся и продолжил с 3-го.
- [ ] Тест: отказ от согласия → `CONSENT_DECLINED`, сообщения не сохраняются.

**Готово, когда:** живой человек открывает ссылку в браузере, проходит все вопросы, закрывает вкладку посреди интервью и продолжает без потерь. Заявка переходит в `IN_PROGRESS`, а после последнего вопроса сессия становится `FINISHED`.

## Этап 3. AI-шаги интервью

### 3.1. LLM Gateway (Кондратов)
- [ ] `llm/ollama.py`: `/api/chat`, `format: "json"`, таймаут 30 с, 2 повтора.
- [ ] `complete_json()`: парсинг, валидация Pydantic, повтор с текстом ошибки в промпте.
- [ ] Загрузчик промптов по имени и версии (`llm/prompts.py`).
- [ ] Журнал `llm_call` без ПДн: purpose, модель, версия промпта, задержка, валиден ли JSON.
- [ ] Фейковый провайдер `FakeLLM` для тестов: возвращает заранее заданные ответы.

### 3.2. Анализ ответа и уточнения (Кондратов)
- [ ] `analyzer.py`: один вызов → `{intent, completeness, missing_points}`.
- [ ] Подключить `policy.decide()` в engine вместо заглушки «всегда полный».
- [ ] `followup.py`: генерация уточнения; проверка длины (до 25 слов) и того, что это вопрос.
- [ ] Резервный вариант: если LLM недоступна или ответ невалиден, считать ответ полным и идти дальше. Интервью не должно падать из-за модели; случай помечается в журнале.

### 3.3. Вопросы кандидата и уход от темы (Кондратов)
- [ ] `candidate_qa.py`: ответ только по `vacancy.description`, иначе «уточните у рекрутера».
- [ ] `off_topic` → вежливый возврат к текущему вопросу без траты лимита уточнений.
- [ ] `wants_to_stop` → подтверждение и пауза (не завершение: кандидат может вернуться).

### 3.4. Guardrails (Кондратов + Мальцева)
- [ ] Вход: длина, повторяющийся текст (флуд), простые маркеры prompt-injection («игнорируй инструкции», «system:», «ты теперь…»).
- [ ] Ответ кандидата всегда передаётся в промпт внутри `<candidate>…</candidate>`, символы тегов экранируются.
- [ ] Выход: стоп-лист оценочных слов (переиспользовать `reporting/validators.py`), запрет цитировать эталон (проверка пересечения с `reference_answer`).
- [ ] Если выход не прошёл проверку → одна перегенерация, затем нейтральная фраза-заглушка.

**Готово, когда:** на 20 тестовых ответах из этапа 0.3 ассистент задаёт уместные уточнения, никогда не превышает 2 уточнения на вопрос и не раскрывает эталон. Prompt-injection из датасета не меняет поведение. Unit-тесты engine с `FakeLLM` зелёные.
