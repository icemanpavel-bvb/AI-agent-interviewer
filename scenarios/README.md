# Сценарии вакансий

Сценарий — JSON-файл с вопросами, критериями и пунктами проверки. Схема: `backend/app/schemas/scenario.py`.
Решения, на которых это основано: `docs/decisions.md` (D-002 — D-005).

| Файл | Вакансия | Тип | Статус |
|---|---|---|---|
| `omto_analyst.json` | Аналитик ОМТО (методика TS-AN-1.0, гайд T06) | собеседование | готов |
| `ml_junior.json` | ML-инженер Junior — **основная** | собеседование | готов |
| `ml_middle.json` | ML-инженер Middle | собеседование | черновик |
| `student_course.json` | Подготовка к экзамену по NLP: банк из 25 вопросов по 8 темам, в сессии 10 случайных | проверка знаний | черновик, нужна проверка эталонов |

## Проверка

```bash
python scripts/validate_scenarios.py
```
Схема проверяет: не больше 10 вопросов и 2 уточнений, уникальность id, существование критериев,
сумму весов 100 % (для готовых), что у каждого критерия с весом есть вопрос.

## Как устроен сценарий

- **`criteria`** — критерии с весом (`weight`), `must_have` и `requires_practice`.
  Критерий с `requires_practice: true` по ответам в чате не закрывается: в протоколе всегда `unknown`.
- **`questions`** — вопросы по порядку (`order` с 1). У каждого:
  - `probes` — пункты проверки, 1–6 шт.: что должно прозвучать в ответе (D-004);
  - `reference_answer` — **пример** сильного ответа для модели, а не образец для сравнения;
  - `evidence_hint` — какие доказательства искать;
  - `max_followups` — 0–2; `required: false` — вопрос можно пропустить.
- **`screening`** — правила для вопроса об опыте: порог стажа (ниже — пометка рекрутеру, не отказ) и пометки.
- **`agent_rules`** — правила поведения агента в этом сценарии.
- **`session`** (только для проверки знаний, D-006) — банк вопросов и выборка на сессию: `size` (до 20), `strategy: balanced_random` (по вопросу из каждой темы, остальные случайно), `allow_topic_choice` (тренировка по одной теме). В собеседованиях — до 10 вопросов, все по порядку.
- **`recruiter_only`** — шкалы 1–4 и заметки. **Никогда не передаются в модель**: для промптов — `Scenario.llm_view()`.

## Как добавить вакансию

1. Скопировать похожий файл, поменять `id` (латиница и `_`), тексты, критерии.
2. Пока работаете — `"status": "draft"`; когда веса и эталоны согласованы — `"ready"`.
3. Запустить `python scripts/validate_scenarios.py`.
4. Загрузка в БД — `scripts/load_scenarios.py` (появится на этапе 1).

Ключи практических кейсов (как CASE-01 из гайда T06) в сценарий **не переносить**.
